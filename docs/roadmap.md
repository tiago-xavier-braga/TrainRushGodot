# Roadmap

Port of Train Rush from Unity to Godot 4.7 (GL Compatibility), as a web game published on
GitHub Pages. The Unity project in `unity/TrainRush/` is the reference: the Godot version must
play the same. Improvements are not part of the port; they go to the backlog.
All project documentation must be kept in the `docs/` folder.

This project is vibe coded: items don't need a design note before code.

## Phase 1: Project base

- [x] Set up the project: folders, input map (WASD / arrows / left stick), web export preset
  (autoloads come with the features that need them)
- [x] Write `gdd.md` from the Unity game (`unity/TrainRush/README.md` and its scenes)
- [x] Import the Kenney kits used in the game (train, mini characters, mini market, prototype)
  and the fonts (Luckiest Guy, Montserrat SemiBold)
- [x] Rebuild the station environment (`Environment.unity`): platforms, rails, fences, gates,
  floor markings, camera
- [x] Export an empty web build to make sure the pipeline works

## Phase 2: Core loop

- [x] Player: top-down movement with the camera following
- [x] Pressure plates: trigger an action when the player stands still on them
- [x] Train cycle for each platform: idle, approaching, waiting for signal, departing,
  finalized, then respawn after a timer
- [x] Traffic light and lever that send the train off
- [x] Passengers: spawner, fence-gate queues and one boarding queue per wagon
- [x] Boarding: passengers walk into the wagons until each wagon is full

Notes: the `Economy` autoload (coins, spend) came in here because gates cost coins; coins
are only earned in Phase 3. Plates have no hold/afford animation or sounds yet (Phase 4).

## Phase 3: Economy and progression

- [x] Ticket revenue for each passenger who boards, with floating coin text
- [x] Money UI
- [x] Upgrades from `ProgressionSettings`: unlock wagons, wagon capacity tiers, faster train
  respawn (same prices and multipliers as in Unity)
- [x] Wagon and train models that change with their tier (`TrainData` / `WagonData` 1–7)

Notes: the upgrade plates are placed per station in `lvl_game.tscn` (their layout differs
between the two platforms). The train smoke particles are left for Phase 4.

## Phase 4: Feedback and tutorial

- [x] Animations: wagon boarding, pressure plate (hold/afford), cash register employee, train smoke
- [x] Passenger reactions when they wait too long in the queue
- [x] First-run tutorial with the guide arrow
- [x] Sound effects and music (`unity/TrainRush/Assets/Audio/`)
- [x] Mobile: on-screen joystick instead of the keyboard

Notes: the joystick shows on any touch screen (`DisplayServer.is_touchscreen_available()`);
Unity asked the CrazyGames SDK for the device type instead. Phase 1 wrongly left the
mini-market and prototype models white: their `colormap.png` does exist in Unity, and they
are textured now.

## Phase 5: Save and publish

The game is published only on GitHub Pages: no CrazyGames SDK. Saving uses Save Kit (from He
Who Loses Wins), which keeps one JSON save in the browser's localStorage.

- [x] Save the progress with Save Kit: coins, per-station tiers, unlocked gates and wagons,
  tutorial done. Each station gets its own keys (Unity's shared keys are not ported: there
  are no Unity saves to stay compatible with).
- [x] Platform detection: the touch joystick keeps using `DisplayServer.is_touchscreen_available()`
  (the CrazyGames device type is gone).
- [ ] Publish the web build on GitHub Pages (single-threaded export, since Pages can't send the
  headers threads need).

Notes: the emotes and icons textures were switched to lossless import: Godot had made them VRAM-compressed (10 MB
for the emotes alone), which took the web build from 26 MB to 14 MB.

## Porting notes

| Unity | Godot |
|---|---|
| URP, WebGL | GL Compatibility, web export |
| ScriptableObject data (`TrainData`, `WagonData`, `ProgressionSettings`) | custom `Resource` (`.tres`) in `resources/` |
| ScriptableObject event channels (`OnTrainStateLeftChanged`...) | signals, or an autoload when the event crosses scenes |
| Additive scenes (`Start` → `Environment` + `Game`) | one main scene (`lvl_game.tscn`) with instanced child scenes |
| Start middlewares (CrazySDK init, load save, platform detection) | Save Kit autoload; touch detection in the joystick |
| LeanTween | LeafTween (`addons/leaf_tween`, from He Who Loses Wins) |
| Animator | `AnimationPlayer` (Kenney models) |
| TextMesh Pro, camera-facing text | `Label` / `Label3D` with billboard |
| Input System, on-screen joystick | input map, a touch joystick node |
| FBX models (Kenney) | the same FBX through Godot's importer |
| Unity scenes and prefabs | generated by `tools/unity_port/gen_godot.py` (see below) |
| `GameManager`, `CharacterManager`, `*Controller` wiring in the Inspector | `station.gd` wires each platform in `_ready()` |

The generator writes the environment scenes, the train/wagon/traffic-light models and the
layout of `station.tscn` (markers, gates, wagon queues, spawner) from the Unity positions. The
gameplay scenes it places (`train.tscn`, `fence_gate.tscn`, `traffic_light.tscn`, `player.tscn`)
are hand-written and never overwritten.

Unity is left-handed and mirrors FBX models on X when importing them. The generator converts
every transform (z → -z) and turns FBX meshes 180° around Y, so the positions in the Godot
scenes match the Unity ones with the sign of z flipped.

## Backlog

- Decide on the Unity quirks listed at the end of `gdd.md` (shared save keys between the two
  stations, empty tutorial save key, speed upgrade capped before the last train models,
  wagon/train model tiers, tutorial ending on the first departure).
- Lighting was retuned to look cozy rather than to match Unity's numbers: warm light at energy
  1.1, ambient 0.3, cream depth fog to 300 m (Unity: light 2, grey fog, which blew out the
  scene in Godot). Values live in `tools/unity_port/gen_godot.py`.
